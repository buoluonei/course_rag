# 简历项目描述

## 课程资料 RAG 问答系统

基于 FastAPI、MySQL 与大语言模型构建的课程资料问答系统：上传 TXT 资料后自动分块入库，提问时检索相关资料片段，生成带来源引用的回答，并支持多轮对话与问答历史。

**技术栈**：Python、FastAPI、MySQL、OpenAI 兼容 API、HTML/JavaScript

**核心功能与亮点**

- 文档管理：资料按文档-分块一对多建模，支持上传、列表、删除；同名文件通过 409 + `overwrite` 参数实现“确认覆盖”，并用数据库唯一约束兜底
- RAG 检索：中文停用词过滤 + 两字组合关键词检索，按命中次数排序取 Top-5 作为模型上下文，回答附带文件名与原文引用
- 多轮对话：通过 `session_id` 保存会话历史，将历史问答组装为 `user/assistant` 消息后调用模型
- 分块优化：固定长度 + 重叠窗口分块，避免长文边界信息丢失
- 工程实践：参数化 SQL 防注入、`textContent` 防 XSS、输入校验与明确的状态码（400/404/409/503）、网页 + Swagger 双入口

**简历可用版本（约 150 字）**

> 课程资料 RAG 问答系统：基于 FastAPI、MySQL 与大语言模型的资料问答平台。支持 TXT 上传、按文档-分块建模、同名覆盖、中文关键词提取与相关度排序检索（Top-5 上下文）、来源引用、多轮会话与问答历史。所有 SQL 参数化执行，前端渲染采用 textContent 防注入，并提供网页与 Swagger 双入口。

## 面试可深入的话题

- 为什么先删停用词再生成两字组合，而不是直接用整句话搜索
- 为什么分块要有重叠；块大小如何权衡
- 为什么“先校验新文件，再删旧文档”，顺序错了会怎样
- 同名覆盖为什么返回 409，而不是 400 或自动覆盖
- 多轮对话为什么历史只存问题+回答，资料每轮重新检索
- 参数化查询如何防止 SQL 注入
- 检索排序的简单方案是什么，真实系统会怎么升级（向量检索 + 重排）
